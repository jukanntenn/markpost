# MRFC: Layered agent instructions and direction-free CLAUDE.md mirrors

Status: implemented

English | [中文](2026-08-22-layered-agent-instructions-and-direction-free-mirrors.zh.md)

## Problem

The root `AGENTS.md` — and its byte-identical `CLAUDE.md` copy — carried every subtree's detail for four technology stacks: per-area command blocks, migration rules, Go and TypeScript style, per-stack testing contracts, and mixed boundaries, 1,172 words that every session loaded in full regardless of task. Layering had already begun (`docs/AGENTS.md` owns the documentation standard, [`../AGENTS.md`](../AGENTS.md) owns the MRFC standing orders), but the three code workspaces had no layer of their own, nothing mechanical pushed subtree detail out of the root, and nothing bounded the files that tax every session — the [2026-08-21 verdict](./2026-08-21-documentation-gates-and-mrfc-system.md) had ported the reference project's gates selectively and deferred word budgets until a trigger signal appeared; four-stack accretion in the root was that signal. The mirror mechanism itself was defective: `sync_agents.py` copied `AGENTS.md` → `CLAUDE.md` directionally, a primary/secondary relationship. An agent whose tool loads `CLAUDE.md` and edits it gets that edit silently clobbered by the older `AGENTS.md` the moment sync runs — exactly the stale-overwrites-fresh failure a mirror must never commit.

## Decision

**Layers with budgets.** The root keeps what every session needs — identity, tech stack, the layout map, the cross-area command index (`dev.py`, `doc_sync`), git workflow, cross-area boundaries, and an "Editing these instructions" section — and lands at 576 words under an 800-word ceiling. Three subtree files carry the workspace-specific orders: `backend/AGENTS.md` (Go commands, migration rules, Go style, testcontainers contracts, backend-only prohibitions) ≤ 500, `frontend/AGENTS.md` (pnpm commands, React/TypeScript style, the static-export constraint, Vitest) ≤ 300, `e2e/AGENTS.md` (commands, chromium-only, dagger fidelity) ≤ 150. A subtree file supplements the root and never repeats it; the root's layout map links each one. `devops/`, `scripts/`, and `specs/` got no file: deploy procedures live in `docs/`, gate contracts in [`docs/AGENTS.md`](../../../docs/AGENTS.md), and `dev.py` commands are the repo-wide entry the root owns.

**Direction-free mirrors.** The four agent-instruction trees — the root, `backend/`, `frontend/`, `e2e/` — each hold a byte-identical `CLAUDE.md` beside `AGENTS.md`; `docs/AGENTS.md` and `.agents/mrfcs/AGENTS.md` are standing orders about documents and stay single-file. A pair has no primary. Direction resolves per pair against git HEAD — never mtime, which clone and checkout reset: exactly one side differing from HEAD means that side is copied over the other, so fresh updates stale; equal contents pass; both sides differing and disagreeing is a conflict the tooling refuses to guess through. A path absent from HEAD counts as changed on its side, which bootstraps new pairs.

**Renamed tooling, self-healing gate.** `check_agent_instructions.py` (gate) and `sync_agent_instructions.py` (fixer) share the detection module [`agentlib.py`](../../../scripts/agentlib.py) — "agent instructions" is the agents.md ecosystem's own term for these files and drops the subagent-ambiguous `agents` naming, hook id `agents-sync` included. The [prek](../../../prek.toml) hook `agent-instructions-sync` widens its filter to subtree pairs and, on an unambiguous single-sided change, updates and stages the stale twin itself; only a true conflict or a deletion fails, and that failure names the sides, the fix command, and the manual reconciliation steps, so an agent reading it knows exactly what to do. [CI](../../../.github/workflows/docs.yml) path filters follow the rename.

**Word budgets.** [`verify_doc_budgets.py`](../../../scripts/verify_doc_budgets.py) with [`doc_budgets.manifest.json`](../../../scripts/doc_budgets.manifest.json) — `wc -w` whole-file ceilings, a budgeted file gone missing failing the gate so renames cannot orphan budgets — joins [`doc_sync.py`](../../../scripts/doc_sync.py). Budgets are ceilings, not reduction targets: on red, relocate to the owning tier, then condense, and raise the ceiling last with the manifest diff justified in the PR. Ceilings sit below the reference project's (root 800 vs 1,600; subtrees 500/300/150 vs a 600 default) because the post-split content fits in less; `docs/AGENTS.md` gets 600, having grown to carry the subtree tier row and the budget rule.

**Docs follow.** `docs/AGENTS.md` gained the subtree-AGENTS tier row, the budget rule, and the slop case of a subtree file restating the root; the doc-standards skill carries the updated workflow; the root's "Editing these instructions" section states the mirror contract (edit either side; the tooling keeps the pair equal), the budgets, and the subtree list.

**Bilingual record pairs.** [`verify_mrfc_format.py`](../../../scripts/verify_mrfc_format.py) accepts a `.zh.md` twin beside its same-basename English original — the gate extension shipped with this record, gate and motivating need together. Both skeletons are checked, machine tokens and section headings stay in English, and a pair updates together. This record is the first pair, on the maintainer's instruction, relaxing the records-stay-English-only fact in the [tree contract](./2026-08-22-agents-mrfcs-tree-and-contract-split.md); the [MRFC README](../README.md) states the twin contract. The skills mirror stays directional (`.claude/skills/` → `.agents/skills/`); promoting `.agents/` to the source remains that contract's recorded future work.

## Alternatives considered

**Symlink mirrors — the reference project's mechanism.** Zero drift by construction: one inode, two names. It lost: git stores a symlink as a mode-120000 blob holding the target path, and a Windows checkout without `core.symlinks=true` plus Developer Mode or admin materializes `CLAUDE.md` as a regular file containing the nine bytes `AGENTS.md`; creating symlinks needs privilege there, and archive transports and several network filesystems mangle links. Nothing constrains contributors to Unix-like checkouts, so the first Windows clone trades drift risk for a broken mirror.

**Keep one large root file.** It lost: every session pays for every stack's detail whether or not the task touches it, while the load paths already support progressive disclosure — Claude Code pulls in a subtree `CLAUDE.md` when it reads files there, Codex merges `AGENTS.md` files along the cwd chain — so layering localizes the context tax where tools support it and the root's links serve the rest. Without a mechanical budget the accretion also continues: the reference project's own tiers-and-budgets record documents prose discipline failing without a backstop.

**Keep directional sync (status quo).** It lost: directionality is the defect, not a tuning choice — whichever side is named secondary has its edits silently reverted by the fixer, precisely on the side whose tool loads it and whose agent therefore most likely edited it.

**mtime-based direction detection.** It lost: clone and checkout reset mtimes to now, making both sides equally new; content comparison against HEAD is deterministic and depends on no filesystem state.

**Per-tool native rule files (`.cursor/rules`, copilot instructions, and friends).** It lost: one fact gains a home per tool and drifts between them; the mirror keeps one content under per-tool filenames at zero marginal authoring cost.

**Reference-aligned budget numbers (root 1,600, subtree 600).** It lost: the post-split content fits comfortably below them — the root lands at 576 words — and higher ceilings would license growth the content does not need.

## Consequences

The mirror matrix was exercised in a scratch clone: single-sided edits on either side of a pair were auto-fixed and staged by the gate, identical edits on both sides passed, disagreeing edits failed with output naming the sides and the reconciliation steps, adding one side of a new pair bootstrapped the twin, and an unborn HEAD (no first commit) still enforced pair equality. `doc_sync` runs green over the corpus with the budget gate included, and removing a budgeted file fails it; root↔subtree cross-links resolve through the link gate, which scopes the new `AGENTS.md` files as ordinary Markdown. The costs accepted: the hook now mutates staged content, bounded by deterministic detection (only the exactly-one-side-changed case auto-fixes; both-sides-changed never guesses); direction detection reads HEAD, so merge or rebase states that leave a pair disagreeing surface as conflicts with guidance, never as silent copies; tight ceilings invite raise-churn, absorbed by headroom and the documented raise path; and paired records add a translation duty on every update of a paired record, with pairs optional per record. Pairs became mandatory for every record in [the bilingual-pairs MRFC](../proposed/2026-08-22-bilingual-documentation-pairs.md).
