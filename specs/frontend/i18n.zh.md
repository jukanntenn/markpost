# 前端国际化

[English](i18n.md) | 中文

本文档定义前端 i18n 架构。后端 i18n 见 [backend/i18n.zh.md](../backend/i18n.zh.md)；前后端联动见本文档末尾。

<a id="technology-stack"></a>

## 技术栈

前端使用 [next-intl](https://next-intl.dev/)（v4.7.0）做客户端消息本地化，**纯客户端模式** —— 不使用 `getRequestConfig` / `next-intl/plugin` / `i18n/request.ts`（这些是服务端装配，纯静态导出不可用，详见 [build.zh.md](./build.zh.md) §3）。

> 依据（next-intl 源码）：`NextIntlClientProvider` 是 `'use client'` 组件（`NextIntlClientProvider.tsx:1`），只接收 `locale` + `messages` props 即可工作，不依赖服务端。`getRequestConfig` / `i18n/request.ts` 是 "server-only"（`configuration.mdx:16`）。纯静态导出跳过这些，直接给 provider 传 props。

<a id="supported-locales"></a>

## 支持语言

与后端对齐，支持 4 种语言（BCP 47 标签）：

| 标签      | 语言             | 默认 |
| --------- | ---------------- | ---- |
| `en`      | English          | ✅   |
| `zh-Hans` | 简体中文         |      |
| `zh-Hant` | 繁体中文（台湾） |      |
| `ja`      | 日本語           |      |

```typescript
// src/i18n/constants.ts
export const availableLocales = ["en", "zh-Hans", "zh-Hant", "ja"] as const;
export type Locale = (typeof availableLocales)[number];
export const defaultLocale: Locale = "en";
```

> **BCP 47 对齐**：前端用 `zh-Hans` / `zh-Hant`（区分简繁），与后端 locale 标签一致。发请求时 `Accept-Language` 直接传当前 locale，后端能精确匹配。不使用不区分简繁的 `zh`。

<a id="locale-files"></a>

## Locale 文件

```
src/i18n/locales/
├── en.json         English (baseline)
├── zh-Hans.json    Simplified Chinese
├── zh-Hant.json    Traditional Chinese
└── ja.json         Japanese
```

每语言一个 JSON 文件，嵌套对象按 namespace 分组：

```json
{
  "dashboard": {
    "postKey": {
      "title": "Post Key",
      "description": "Use this key to..."
    }
  },
  "common": {
    "save": "Save",
    "cancel": "Cancel"
  }
}
```

<a id="translation-key-naming"></a>

### 翻译 key 命名

dot-separated、feature 前缀，与后端消息 ID 风格一致：

- `dashboard.postKey.title` —— dashboard 功能，post key 区
- `login.username` —— 登录页
- `common.save` —— 共享翻译

namespace 映射路由结构和组件组织。

<a id="locale-detection-and-persistence"></a>

## 语言检测与持久化

<a id="detection-priority"></a>

### 检测优先级

```typescript
// src/utils/i18n.ts
// matchesLocale reports whether a BCP 47 tag matches one of our supported
// locales. Chinese is special-cased: zh-Hans matches zh-CN/zh-SG (Simplified),
// zh-Hant matches zh-TW/zh-HK (Traditional).
function matchesLocale(tag: string, locale: Locale): boolean {
  const lower = tag.toLowerCase();
  if (lower === locale.toLowerCase()) return true;
  if (locale === "zh-Hans") return lower === "zh-cn" || lower === "zh-sg";
  if (locale === "zh-Hant")
    return lower === "zh-tw" || lower === "zh-hk" || lower === "zh-mo";
  if (locale === "en") return lower.startsWith("en");
  if (locale === "ja") return lower.startsWith("ja");
  return false;
}

export function getDefaultLocale(): Locale {
  if (typeof window === "undefined") return "en";
  // 1. localStorage
  const stored = localStorage.getItem(STORAGE_KEY);
  if (stored && availableLocales.includes(stored as Locale))
    return stored as Locale;
  // 2. browser languages, matched against the supported tags
  for (const candidate of navigator.languages) {
    for (const locale of availableLocales) {
      if (matchesLocale(candidate, locale)) return locale;
    }
  }
  // 3. fall back to en
  return "en";
}
```

检测顺序：先看 localStorage 里的已存偏好；然后用 `navigator.languages` 与支持标签匹配（`zh-Hans` 亦匹配 `zh-CN` / `zh-SG`，`zh-Hant` 亦匹配 `zh-TW` / `zh-HK` / `zh-MO`）；最终回退 `en`。

<a id="persistence"></a>

### 持久化

```typescript
export function persistLocale(locale: Locale): void {
  localStorage.setItem("locale", locale);
}
```

**只存 localStorage**，不写 cookie（后端用 `Accept-Language` 头检测，不用 cookie）。

<a id="dynamic-message-loading"></a>

## 动态加载 messages

locale 切换时动态 import 对应 JSON 文件（构建时打成独立 chunk，按需加载）：

```typescript
export async function loadMessages(locale: Locale) {
  return (await import(`@/i18n/locales/${locale}.json`)).default;
}
```

<a id="provider-assembly-pure-client-side-bootstrap"></a>

## Provider 装配（纯客户端自举）

`LocaleProvider` 是 `'use client'` 组件，用 `NextIntlClientProvider` 包裹应用。**不接收 serverLocale / serverMessages props** —— 根 layout 不调服务端 i18n API。

```tsx
// src/components/providers/LocaleProvider.tsx
"use client";

export function LocaleProvider({ children }: { children: React.ReactNode }) {
  const [locale, setLocaleState] = useState<Locale>(defaultLocale);
  const [messages, setMessages] = useState<AbstractIntlMessages>({});
  const [ready, setReady] = useState(false);

  // after hydration: read the stored locale and load its messages chunk
  useEffect(() => {
    const stored = getDefaultLocale();
    loadMessages(stored).then((m) => applyMessages(stored, m));
  }, [applyMessages]);

  const setLocale = useCallback(async (newLocale: Locale) => {
    const m = await loadMessages(newLocale);
    applyMessages(newLocale, m);
    persistLocale(newLocale);
  }, []);

  return (
    <LocaleContext.Provider value={{ locale, setLocale, availableLocales }}>
      {ready ? (
        <NextIntlClientProvider locale={locale} messages={messages}>
          {children}
        </NextIntlClientProvider>
      ) : (
        <AppShellSkeleton />
      )}
    </LocaleContext.Provider>
  );
}
```

**首个 messages chunk 解析完成前 children 不挂载**，渲染中性的 `AppShellSkeleton` —— 没有任何 `useTranslations` 调用带着空 messages 运行，用户看到的是中性骨架，而不是未翻译的 key 一闪而过。`applyMessages` 还把 locale 与 messages 发布到模块级槽位（`src/i18n/current.ts`、`src/i18n/messages.ts`），让非 React 的 API client 能发送 `Accept-Language` 并解析错误消息文本。

> 根 layout 不调用 `getLocale()` / `getMessages()`（这些是 `next-intl/server` API，纯静态导出不可用）。详见 [architecture.zh.md](./architecture.zh.md) 的 Provider Stack。

<a id="usage-in-components"></a>

## 在组件中使用

用 `useTranslations(namespace?)` hook（next-intl 提供）：

```typescript
import { useTranslations } from "next-intl";

function PostKeySection() {
  const t = useTranslations("dashboard.postKey");
  return <h2>{t("title")}</h2>;
}
```

`useTranslations` 的 namespace 参数可选 —— 不传则返回所有 messages。namespace 支持点号嵌套（`useTranslations("dashboard.postKey")`）。

`useLocale()` 返回当前 locale（来自 provider 的 `locale` 值）。

<a id="translation-workflow"></a>

## 翻译工作流

前端 locale 文件**手动维护**，`en.json` 为基准。条目不多（每语言约 185 个 key），手动维护足够。

新增翻译 key 时：在 `en.json` 加条目 → 翻译到 `zh-Hans.json` / `zh-Hant.json` / `ja.json`。

> 后端用 goi18n extract/merge 工作流（见 [backend/i18n.zh.md](../backend/i18n.zh.md)），前端不引入提取工具（next-intl 不绑定特定提取工具，引入额外复杂度无收益）。

<a id="frontend-backend-contract"></a>

## 前后端联动

| 维度         | 规范                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------- |
| 语言范围     | 前后端一致：en / zh-Hans / zh-Hant / ja                                                           |
| 标签         | 前后端一致：BCP 47                                                                                |
| 语言传递     | 前端 API client 每请求带 `Accept-Language: <当前 locale>`；后端按此头翻译错误消息                 |
| 消息 ID 风格 | 前后端一致：dot-separated feature 前缀（前端 `login.username`，后端 `error.invalid_credentials`） |

用户选语言 → `persistLocale` 存 localStorage → API client 读当前 locale → 每请求带 `Accept-Language` 头 → 后端返回对应语言的错误消息。
