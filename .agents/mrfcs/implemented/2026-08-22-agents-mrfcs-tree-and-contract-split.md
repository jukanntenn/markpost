# MRFC: The .agents/mrfcs tree and its two-document contract

Status: implemented

English | [中文](2026-08-22-agents-mrfcs-tree-and-contract-split.zh.md)

## Problem

The MRFC system's single README carried two jobs at once: the durable contract of the mechanism (layout, lifecycle, format) and the session-critical orders an agent needs on every touch (grep before writing, never rewrite a decision). An agent landing in the tree had no AGENTS.md to load, so those orders lived only in a document the agent had to know to open. The tree also sat at the repo root (`mrfc/`) while the repo's agent-loaded resources were converging under `.agents/` — the directory AI agent tools treat as their load path, the placement the deepseek-harness reference project uses for its own notes. A naive move would have silently stripped every documentation gate from the corpus: the prek `doc-check` hook excluded `^\.agents/` wholesale and no gate's PATTERNS scanned inside `.agents/`. Finally, the README self-described as "a decision record" — ADR framing that covers only the retrospective half of a corpus whose lifecycle also holds proposals requesting review and rejected verdicts.

## Decision

The tree lives at `.agents/mrfcs/` (moved with `git mv`, history preserved): `.agents/` is where AI agent tools load repo resources — skills today, MRFCs now — matching the reference project's placement without importing its machinery. The tree carries two documents with orthogonal jobs: [`AGENTS.md`](../AGENTS.md) holds standing orders only — duplicate check, supersede-don't-rewrite, keep the bilingual pair in sync — each a trigger linking to the rule's home; [`README.md`](../README.md) remains the single normative contract. `README.zh.md` mirrors the README section-for-section, machine tokens (`# MRFC:`, `Status:`) in English and explicit ASCII anchors so fragment links resolve identically in both languages; records stayed English-only until bilingual record pairs landed ([the layered-instructions MRFC](./2026-08-22-layered-agent-instructions-and-direction-free-mirrors.md)). Terminology is calibrated to the essence: MRFCs are markpost's RFCs — durable proposals and decision records — and "MRFC" is the noun everywhere, retiring the ADR-flavored self-description. The gates follow the tree: [`verify_mrfc_format.py`](../../../scripts/verify_mrfc_format.py), [`verify_md_links.py`](../../../scripts/verify_md_links.py), and [`verify_md_wrap.py`](../../../scripts/verify_md_wrap.py) scope to `.agents/mrfcs/**`, the format gate allowlists the tree-root files (`README.md`, `AGENTS.md`, `README.zh.md`), and the prek exclusion in [`prek.toml`](../../../prek.toml) narrows from `^\.agents/` to `^\.agents/skills/` so commit-time gating survives the move; [`.github/workflows/docs.yml`](../../../.github/workflows/docs.yml) path filters follow. Recorded direction: `.agents/` is slated to become the true source for agent-loaded resources (today `.claude/skills/` is the source mirrored into `.agents/skills/`); that promotion is future work, and the by-subtree exclusion keeps the gate scope correct through it.

## Alternatives considered

**Keep the tree at the repo root and only add an AGENTS.md.** Lost: `.agents/` is the established load path for agent tooling and the repo's direction makes it the agent side of the repository — decision memory belongs beside the workflows that consume it, and the root stays product-focused. The ADR-community convention of visible `docs/adr/` directories was weighed and set aside: markpost's corpus is agent-first in both authorship and readership.

**Port the reference project's machinery wholesale — class folders, a frozen archive, per-note `.zh.md` + `.i18n.yaml` triplets, per-lifecycle AGENTS.md files, word-budget gates.** Lost: this reaffirms the [2026-08-21 verdict](./2026-08-21-documentation-gates-and-mrfc-system.md) — markpost's corpus is an order of magnitude smaller and its records are single-language; triplet and manifest upkeep taxes every edit while buying nothing at this size. Pieces arrive only on a trigger signal; the AGENTS.md/README split and one bilingual README are this change's triggers.

**Keep self-describing as ADR decision records.** Lost: the corpus is proposals under review and rejected verdicts too, not only retrospective decisions — the reference project itself defines its notes as RFCs written by agents, and "markpost's RFCs" names the whole lifecycle the tree actually manages.

**Move without touching the exclusion rules — let the gates skip `.agents/`.** Lost: link, wrap, and format gating would silently vanish from the corpus — the format gate would report zero files and pass green; enforcement parity is the reason the gates exist, so the exclusion was narrowed by subtree instead.

## Consequences

The MRFC corpus keeps full commit-time and CI gating at its new home; agents working in the tree load the standing orders automatically while every rule stays single-homed in the README. Cross-tree links deepened by one level — 30+ references across specs, docs, skills, and Go comments updated mechanically and re-verified by the link gate. The zh mirror adds a translation-sync duty, carried as a one-line order in the tree's AGENTS.md rather than a pairing manifest. The prek exclusion now names `.agents/skills/` explicitly, so future Markdown under `.agents/` is gated by default instead of excluded by default — the right default, and one to remember when the skills mirror is promoted to true source.
