# MRFC: Read-path performance pass

Status: implemented

English | [中文](2026-07-09-read-path-performance-pass.zh.md)

## Problem

The read path — the product's hot path, targeted at a few hundred reads/second on a 2-core / 2 GB / 3 Mbps VPS with a 1 TB monthly quota — was served with zero caching at any layer: every `GET /:qid` did a fresh Postgres read, goldmark render, bluemonday sanitize, and template execute; responses went out uncompressed with no `Cache-Control`/`ETag`; the page's ~8 KB inline `<style>` block was retransmitted on every view; the Postgres pool was unbounded/untuned; and one global rate limiter coupled read throttling to write throttling. At 375 KB/s egress the origin could carry ~25 compressed responses/second — two orders of magnitude below the target load — so the SaaS reference instance could not function at scale without a systemic redesign.

## Decision

The pass (landed starting `ed16a32`, 2026-07-09) treats transmission minimization as the dominant objective and ships, in application code and deploy templates: three cache layers with different TTLs by invalidation power — browser `max-age=300`, CDN `s-maxage=3600` (Cloudflare free tier), and an unbounded in-process render cache keyed `qid:buildID:{html,raw}` (singleflight-collapsed, ristretto-backed with TinyLFU admission, `[render]`-configurable) — with ETags that hash the **rendered output** (xxhash64 of the minified HTML / of the raw string) so renderer, template, or CSS upgrades change the ETag automatically; deletion endpoints (`DELETE /api/v1/posts/:id`, admin variant) that invalidate the origin cache synchronously and issue a best-effort Cloudflare cache-tag purge asynchronously through a `Purger` interface (no-op when Cloudflare is unconfigured), while `PruneExpired` never purges; edge-cacheable 404s (`max-age=60, s-maxage=60`) to absorb QID-enumeration probes; Caddy `encode zstd gzip`; CSS extracted to `templates/post.css`, minified and content-hash-fingerprinted by `cmd/buildcss` (`go:embed` + `csshash.go`, served at `/static/post.<hash>.css` with `immutable`), and HTML minified at render time by the same `tdewolff/minify` library; four tollbooth limiters — read (100/s per IP), public write (10/min + 1000/day per `user_id`), authed write (30/min per `user_id`), login (5/min per IP) — with gin `ClientIP()` resolution over the XFF chain and Caddy `trusted_proxies` pinned to Cloudflare CIDRs; and Postgres tuning — pool 25/10/30-min, five GUCs (`shared_buffers=256MB`, `effective_cache_size=1GB`, `maintenance_work_mem=128MB`, `max_connections=50`, `synchronous_commit=off`) applied by the deploy templates, lz4 TOAST compression declared in the versioned migration, and a Unix-socket connection to a sibling Postgres container. Specs: [`specs/backend/caching.md`](../../../specs/backend/caching.md), [`compression.md`](../../../specs/backend/compression.md), [`rate-limiting.md`](../../../specs/backend/rate-limiting.md), [`postgres-tuning.md`](../../../specs/backend/postgres-tuning.md). Posts are write-once and immutable — the `UpdatePost` path is removed from the contract, which is what collapses cache invalidation to deletion events.

## Alternatives considered

**Serve directly from the origin at SaaS scale.** Mathematically impossible at 3 Mbps; a CDN is a precondition for the reference instance. A metered CDN (AWS CloudFront, Bunny) was rejected because byte billing re-imposes the 1 TB quota as a cost ceiling (~$660/month at the projected 7.8 TB) where Cloudflare's free tier is unmetered.

**ETag on inputs (`sha256(body+title+cssHash+templateVersion)`), body-only hashes, or SHA-256 itself.** Input hashes miss renderer upgrades and renew stale shells via `304`; SHA-256's cryptographic strength is unnecessary for cache validation and ~20× slower than xxhash, which arrives transitively via ristretto.

**One uniform TTL, `stale-while-revalidate`, or `immutable` on HTML.** A uniform TTL either propagates upgrades too slowly or forfeits CDN benefit; SWR is a documented no-op in the presence of `s-maxage` (RFC 9111 proxy-revalidate semantics) and enabling it would mean dropping `s-maxage` for a ≥2-hour free-tier Edge Cache TTL; `immutable` on a deletable, non-content-addressed URL is factually wrong and would hide deletions from browsers. `"Purge Everything"` as the invalidation mechanism was rejected as a guaranteed thundering herd; avoiding purge entirely was rejected once Cloudflare opened all purge methods to the free tier (2025-04) at rates markpost's deletion volume sits far beneath.

**brotli, Caddy `precompressed`, a Vite/Node or esbuild toolchain for the CSS.** brotli needs a custom Caddy build for marginal gain; precompression only helps the one ~1.8 KB static asset; a Node toolchain is unnecessary for a single self-contained CSS file (esbuild remains a documented escalation if the CSS ever needs bundling).

**A plain LRU / `golang-lru` / `bigcache` / `freecache` for the render cache, or ristretto without singleflight.** Plain LRU is scan-pollution-vulnerable under Zipfian reads; bigcache/freecache target many small uniform entries, not few large HTML blobs; ristretto alone absorbs repeats but not the stampede — singleflight is the load-bearing half (cold-miss bursts, release windows, restarts).

**Static-file materialization or a rendered-HTML DB column.** At 10 000 posts the in-process cache already drives origin render cost near zero; both alternatives add write-time render, cross-process coordination or schema coupling (re-render on every renderer upgrade), and storage, for negligible gain.

**A single global limiter; per-`post_key` L2 keying; a date-keyed daily counter.** The global limiter couples read and write throttling (the original defect); keying L2 on `post_key` lets rotation evade the limit; a UTC-midnight counter duplicates what the token bucket expresses as `1000/86400` per-second rate.

**`gin.PlatformCloudflare` or tollbooth `SetIPLookup` for client IPs.** Both trust a forgeable header with no CIDR validation; the XFF walk with Caddy-side `trusted_proxies` validates the peer at the TCP layer and overwrites non-trusted-peer XFF — self-protecting even against a spoofed-source-IP bypass of the origin firewall.

**A dedicated DB server (shared_buffers at 25% of RAM), Postgres inside the markpost container, or bare-metal deployment.** The box is not a dedicated DB server; in-container Postgres couples failures and complicates backup/scaling; bare metal frees single-digit microseconds while abandoning the reproducible image, one-command self-hosted install, and multi-arch CI — the binding constraint is the 3 Mbps link, which no container layer touches.

**Application-level gzip-into-BYTEA for post bodies.** ~4× compression vs ~3× for TOAST-lz4, but it moves decompression into the Go hot path on every read and changes the column type. Retained as the first escalation step if disk pressure exceeds the ~11 GB estimate, alongside cold-tier offload to object storage.

## Consequences

The origin survives its load envelope with ~$0.20/month marginal cost, upgrades propagate within an hour without operator action, and deletions are near-immediate at the CDN. The obligations accepted: cache correctness depends on output-hashing ETags and deletion-driven invalidation (any new response variant must hash what it serves), the Cloudflare CIDR list in the Caddyfile is an operator-maintained responsibility, the GUC/lz4/socket pieces are deploy-template concerns verified manually rather than in Go tests, and the loadtest suite (`scripts/loadtest/`, capacity report) is the standing evidence that the envelope holds. The disaster-recovery tier (backup tooling) is deliberately out of this record's scope and lives in [the disaster-recovery MRFC](../proposed/2026-07-09-wal-archival-disaster-recovery.md).
