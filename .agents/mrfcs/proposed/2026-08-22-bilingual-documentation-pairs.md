# MRFC: Bilingual documentation pairs

Status: proposed

English | [中文](2026-08-22-bilingual-documentation-pairs.zh.md)

## Problem

The corpus serves readers in two languages — the maintainer works in Chinese, and the first record pair exists on that instruction — but nothing governs which language a page is written in. `specs/` is single-language per file in English, Chinese, or a mid-sentence mix (`auth.md`, `api-design.md`, both `i18n` specs, and `e2e/HANDBOOK.md` are Chinese-native; a dozen-odd others mix languages), `backend/docs/API_SPECIFICATION.md` is a stale Chinese page hiding behind the generated-Swagger exemptions, and the root README pair predates the naming the MRFC tree established (`README_zh.md` against `.zh.md`). A reader gets half the corpus natively and half not at all, and which half depends on the directory. No page keeps step with a counterpart in the other language because no page has one: the bilingual mechanism that exists — optional `.zh.md` twins, exercised by the tree's README and exactly one record — makes single-language files the default, so `PRINCIPLES.md`, the guides, and every historical record are English-only while half the specs are Chinese-only or mixed. The [2026-08-21 verdict](../implemented/2026-08-21-documentation-gates-and-mrfc-system.md) deferred the reference project's bilingual machinery until a trigger signal appeared; serving both language communities across the whole corpus is that signal.

## Proposal

**Equal-authority pairs, one naming.** Every documentation file except agent instructions ships as a pair: `foo.md` in English beside `foo.zh.md` in Chinese, same directory, no locale infix on the English side — `README_zh.md` renames to `README.zh.md` to match the convention the MRFC tree, the first record twin, and the format gate's filename regex already share. Both languages carry equal authority: either side may be authored or edited first, the edited side is the source for that change, and the twin follows in the same change as a minimal patch — never a wholesale re-translation; where a pair substantively disagrees, the side that is wrong is fixed, and neither language wins by default. Scope is the documentation corpus — root README, `PRINCIPLES.md`, `docs/`, `specs/` including the index, `.agents/mrfcs/` including every historical record, `e2e/HANDBOOK.md` — with exemptions in an exclusions-only manifest, `scripts/doc_languages.manifest.json`: agent instructions (every `AGENTS.md`/`CLAUDE.md`/`SKILL.md` and the skills mirror), the ledgers `CHANGELOG.md` and `KNOWN_ISSUES.md` (narrated history, per-entry translation duty, no reader value), `scripts/loadtest/` point-in-time reports, generated Swagger, and `.zcode/`. `backend/docs/API_SPECIFICATION.md` is deleted outright: a stale Chinese duplicate of [`specs/backend/api-schema.md`](../../../specs/backend/api-schema.md) — the endpoint reference's single home — contradicting it on basic facts (base path `/api` against `/api/v1`).

**One gate, five checks.** `scripts/verify_doc_pairs.py` — stdlib Python over `doclib`, staged-restrictable like its siblings, expanding a staged file to its whole pair — enforces: pair completeness in both directions (every in-scope `.md` has its `.zh.md`; no `.zh.md` is an orphan); a language switcher in each side's header region linking its twin; link locale (a relative link into the corpus from a `.zh.md` targets the `.zh.md` variant, from a `.md` the `.md`; targets outside the corpus keep their path); structural parity in its simple form — identical heading-depth sequences and byte-identical fenced code blocks, comments included, because examples are not translated; and language purity — no CJK in the prose of an in-scope `.md`, with per-file manifest exemptions for pages whose subject legitimately requires CJK (`specs/backend/keyword-filter.md` is the expected case) and no reverse check on `.zh.md`, which legitimately carries English terms. It joins [`doc_sync.py`](../../../scripts/doc_sync.py), so the prek staged run and the CI full run enforce it with no new wiring.

**Gates and homes adapt.** `specs/index.md` pairs into `index.zh.md` with translated row summaries, and [`verify_specs_index.py`](../../../scripts/verify_specs_index.py) moves to one row per pair (the stem, not each file). The [MRFC README](../README.md) turns "a record may carry a `.zh.md` twin" into the mandatory contract — every record is a pair, [`verify_mrfc_format.py`](../../../scripts/verify_mrfc_format.py) keeps checking both skeletons with machine tokens and section headings in English, and ASCII anchors beside Chinese headings keep fragment links locale-independent. The `verify_md_*.py` patterns swap `README_zh.md` for `README.zh.md` (directory globs already cover `.zh.md` siblings); the docs workflow's path filter adds the new manifest. The contract itself — equal authority, the switcher, link locale, code-fence identity, half-width spaces between CJK and Latin, full-width punctuation, a seed terminology table, and the note that document `.zh` corresponds to the application's `zh-Hans` locale (the app's own i18n is untouched) — becomes rule 7 in [`docs/AGENTS.md`](../../../docs/AGENTS.md) with the manifest linked; the root `AGENTS.md` carries one line pointing at it; the `doc-standards`, `writing-mrfcs`, and `commit` skills follow.

**The corpus normalizes in one change-set.** A per-file language audit sorts every in-scope page into English-only (a twin is written), Chinese-native (English content goes into the `.md`, the Chinese text is cleaned into the `.zh.md`), or mixed (split properly into both) — roughly fifty files, landed as tiered commits in a single change-set: mechanism, small pairs, the MRFC back-catalogue, then `specs/` in waves, each commit staging complete pairs and the full-corpus CI run validating the end state. Historical records translate too: a two-class corpus would hand the Chinese reader everything except the decision history — the why the MRFC system exists to carry — for a bounded one-time cost. `PRINCIPLES.md` pairs as well; its scheduled deletion removes the pair with it.

**The mechanism grows on signals, not speculatively.** Declined for now, each with the trigger that would revive it: per-pair blob-hash sidecars and freshness records (one-sided prose edits repeatedly slipping through review); a PR-level co-change diff gate (single-sided pair incidents); full structural signatures over tables and lists (structural drift); a standalone terminology file with forbidden renderings (inconsistent term translations surfacing in review); translation briefings, a dedicated translation skill, or an MT pipeline (whole-file translation becoming routine); merge drivers for pairing metadata (reference-project scale). The reference project's machinery — roughly 5,300 lines of TypeScript serving about 1,150 pairs — is the recorded ceiling of where this road leads, not the starting point.

## Alternatives considered

**Port the reference project's bilingual machinery wholesale** — `.md` + `.zh.md` + `.i18n.yaml` blob-hash consistency records, structural signatures over headings, tables, lists, and links, a translation-briefing generator, a sealed archive, and a git merge driver. It lost: about 4.6 lines of tooling per pair against a corpus of fifty, a sidecar re-record tax on every documentation edit, and a dependency shape (Node toolchain, mdast) the Python-stdlib gate suite deliberately avoids. This record executes the 2026-08-21 trigger clause as designed; it does not reverse the verdict.

**Rules without a gate.** Prose in `docs/AGENTS.md` asking authors to keep pairs in step. It lost: undisciplined drift was the exact failure the 2026-08-21 gates exist for, and every rule in the standard names the gate that enforces it — a bilingual rule without machinery re-creates that failure in two languages.

**Locale directories (`en/` and `zh/` subtrees).** It lost: side-by-side pairs keep the twin in the same diff and the same review, and let a link switch locale by suffix; directories split each page from its own maintenance and turn the link graph into two trees to keep honest.

**English primary, Chinese as translation.** It lost: the requirement is equal authority, and the corpus already disagrees with primacy — several pages are Chinese-native because Chinese is the maintainer's stronger language; a primary rule would demote the side more likely to be authored first and re-file existing Chinese pages as derivatives of translations that do not exist.

**Keep the `README_zh.md` naming.** It lost: `.zh.md` is already the established convention — the tree README, the first record twin, and the format gate's filename regex all use it; two spellings for one idea is its own drift.

**Grandfather the back-catalogue** — historical records and `PRINCIPLES.md` stay single-language, new files pair. It lost: a two-class corpus whose Chinese half loses the decision history for a bounded one-time cost, and an exemption class that would outlive its justification as records accumulate.

## Acceptance criteria

- `python3 scripts/doc_sync.py` is green over the full corpus with the new gate registered: every in-scope file paired in both directions, switchers present, links locale-correct, heading sequences and code fences identical, no CJK in `.md` prose outside manifest exemptions.
- `README_zh.md` is gone (renamed with history), `backend/docs/API_SPECIFICATION.md` is deleted, `specs/index.md` has its zh twin with one row per pair, and no in-scope page remains mixed-language.
- A one-sided structural edit (a heading removed from one side) fails the gate in staged mode and in the full-corpus run — exercised once in a scratch state and reverted; one-sided prose edits are stated as beyond this tier's machinery and name the first signal-gated upgrade.
- The contract is live as rule 7 in `docs/AGENTS.md` with the manifest linked, the root `AGENTS.md` points to it in one line, the `doc-standards`, `writing-mrfcs`, and `commit` skills carry the workflow, and the two superseded records ([2026-08-21](../implemented/2026-08-21-documentation-gates-and-mrfc-system.md), [layered-instructions](../implemented/2026-08-22-layered-agent-instructions-and-direction-free-mirrors.md)) carry one-line pointers back to this record.

## Risks

No gate checks meaning: structural parity proves the pair speaks in the same shape, not that it says the same thing — semantic equivalence stays a review duty, and a sloppy twin passes green. Byte-identical code fences and the CJK purity check can false-positive on pages whose subject is multilingual; the policy is examples-stay-untranslated, and per-file manifest exemptions absorb the genuine cases, each with its reason recorded beside it. `docs/AGENTS.md` sits near its 600-word ceiling and gains a rule — condense first, raise the ceiling last with a justified manifest diff. The ~50-file normalization is reviewable only by spot-check plus gates, and every future documentation change carries a bilingual duty — the accepted tax, proportionate to a corpus an order of magnitude smaller than the reference's.
